DEVELOPMENT STORY

A WEEKEND PROJECT BY A SMALL PRODUCT TEAM

How it started

We built this app together over a weekend. My kids — bekindhearted and titan — helped design the point system and the approval workflow while I coded it. They were the product team. I was the engineer.

Our product team

  • Product designers: The kids decided what features mattered
  • QA team: They find bugs while using it daily
  • Bug reporters: We report issues to each other at dinner
  • Developer: I fix the bugs, sometimes with their help

It's a work in progress. We're still iterating, still fixing things, still adding features when we need them. That's what makes it ours.

The tech stack

React + Supabase in a single HTML file. No build tools, no complexity. Edit the file, push to GitHub, done.

Why a single HTML file?

React loaded via CDN. No webpack, no npm install. Edit the file, refresh the browser, see the changes. Perfect for rapid iteration when you're building with your kids on a weekend.

Why Supabase?

PostgreSQL with a free tier. No server to write. Chore logs sync across devices in the background. Row Level Security keeps the data private.

What the kids designed

The approval workflow — Parents approve chores before points count. This became non-negotiable after someone claimed "clean room" without cleaning their room.
The daily card system — Kids weren't using the app unprompted. So we changed it: instead of asking what they want to do, the app tells them what needs to be done today. 3 chores, 25 minutes, submit when done.
Escalation — Skip sweeping the floor and it costs 6 minutes on day one, 18 minutes after a week. The card gets heavier when you fall behind. The reward for consistency is a lighter card.

How we work as a team

We find bugs together. One kid notices something isn't working. They report it. We fix it. The bugs have made the app better every time.

Things we fixed along the way

Bug: Someone claimed a chore three times in one day. Fix: Per-player daily card — one card per day, can't be changed once submitted.
Bug: Kids weren't opening the app on their own. Fix: Daily Discord reminder at 8 AM — "your cards are ready."
Feature request: Make chores that pile up more visible. Fix: Escalation indicators — ! for neglected, !! for long overdue — and the time cost goes up.
Bug: App had a purple/cyan video game aesthetic. Fix: Stripped to pure terminal — black, white, one green accent.

Key lessons

Build with your users. The kids designed the features. I wrote the code. We tested it together.
Start simple, add what you need. Features emerged from actual use. Nothing was designed ahead of the problem.
Complexity is optional. One HTML file. No build tools. Change it in 60 seconds.
Push tasks, don't ask. "Pick a chore" didn't work. A daily card that says "here's what to do" does.
Bug reports are a gift. When your users find bugs and tell you clearly, you're building the right thing for the right people.

The bottom line

GyattChores is exactly what it should be: something we built together for ourselves.

We're a product team of three. We find bugs, report them to each other, and fix them. The app is a work in progress. So is parenting. That's fine.

What's next

iOS App Store release. Apple Watch complications. Lock Screen widgets. Spanish localization. But first: making sure the kids actually use it every day.

Sometimes "works for us" is all that matters.
